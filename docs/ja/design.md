# 設計原則

`dds_frame` は SUSANOO 全体の代替ではなく、既存の通信フレーム群と並列に利用できる独立したDDS通信部品です。

- 制御クラスは通信から完全に独立し、デバイス固有APIの正本です。
- フレームは制御APIの統一、機器管理、アクセス権、ワークフロー、ROS 2互換性を規定しません。
- RPCは既存の制御クラスを遠隔から透過的に呼び出すための任意の通信形態です。
- Pub/SubはRPCに従属しない独立したDDSの通信形態です。多対多の配信に利用できます。
- DDSのDomainとTopicを使い、独自のネットワーク探索・デバイスDBは実装しません。
- 通信が失敗した際、遠隔メソッドが実行されたかどうかは一般には判定できません。要求IDによる重複抑制は同一サーバープロセス内の有限キャッシュに限られ、厳密なexactly-once保証ではありません。
- `AsyncDeviceClient` は `asyncio.to_thread` による非同期インターフェースであり、サーバー側制御処理の非同期実行を保証しません。
- 現行の`FrameMessage`は独自IDL型です。ROS 2との直接相互運用はできません。
- `msgpack`で表現できない任意のPythonオブジェクトは自動転送されません。

## 未実装・今後の検証

QoS設定の外部公開、型スタブ自動生成、複数クライアント同時負荷、ネットワーク断後の再接続、異なるDDS実装との相互運用は未実装または未検証です。
